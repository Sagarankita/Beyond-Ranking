# DEA efficiency benchmark

## Model and interpretation

The Phase 2 implementation uses an input-oriented Banker-Charnes-Cooper (BCC) envelopment
model with variable returns to scale. For evaluated decision-making unit `o`, it solves:

```text
minimize theta

subject to
  sum_j lambda_j * x_ij <= theta * x_io    for every input i
  sum_j lambda_j * y_rj >= y_ro            for every output r
  sum_j lambda_j = 1
  lambda_j >= 0 and 0 <= theta <= 1
```

`theta` is the radial input-efficiency score. For example, `theta = 0.80` means the model
found a convex peer combination that produces at least the observed outputs with 80% of
the evaluated unit's radially contracted inputs. It does not prove that a 20% real-world
resource reduction is feasible or causal.

The implementation also returns:

- peer DMUs and their `lambda` weights;
- radial and strong-efficiency flags;
- input and output slacks;
- peer-projected input/output targets and percentage gaps;
- solver status, message, and iteration count for every DMU.

The LP is solved using SciPy's HiGHS-backed `scipy.optimize.linprog`, following its
[official linear-programming contract](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html).
Inputs and outputs are divided by positive cohort medians for numerical conditioning;
reported targets remain in original units. Positive unit-rescaling tests confirm that
scores are unchanged.

## Cohort and variables

The only available cohort is the 521-row legacy synthetic fixture. It is generated by a
single formula and can test the mathematics and reporting pipeline, but it is neither a
verified department cohort nor empirical institutional evidence. The configured method
fixture uses three inputs and two outputs:

| Role | Variable | Rationale and limitation |
| --- | --- | --- |
| Input | `research_budget` | Synthetic nominal INR resource; no verified base year |
| Input | `research_fte` | Derived from faculty counts and synthetic research fractions |
| Input | `teaching_load_per_faculty` | Treated as resource pressure; its unit is a synthetic load index |
| Output | `papers_t1` | Synthetic publication count |
| Output | `citation_percentile_avg` | Synthetic quality index, separate from paper volume |

VRS is a defensible first method because the synthetic rows differ greatly in scale and
the proposal concerns departments/institutions of different sizes. This is a modeling
choice, not an established fact about the future observed cohort. Constant returns to
scale, output orientation, alternative variables, and leave-one-out sensitivity should
be compared after a comparable observed cohort is obtained.

Run the fixture with:

```sh
make dea
```

The configuration is `configs/dea/legacy_synthetic_method_fixture.json`; results are
written under `artifacts/dea/legacy_synthetic/`.

## Validation and edge cases

Before solving, the model requires unique DMU identifiers, a single declared cohort,
strictly positive finite inputs, non-negative finite outputs, at least one positive output
per DMU, and non-constant selected variables. Missing values, mixed periods/cohorts,
duplicate IDs, negative values, zero inputs, all-zero output rows, and degenerate constant
variables fail with explicit errors rather than being silently imputed or perturbed.

The benchmark reports the common discrimination heuristic
`n >= max(3 * (inputs + outputs), inputs * outputs)`. It also warns when more than 30% of
solved DMUs are strongly efficient or duplicate input/output profiles are present. These
are diagnostics, not guarantees that a larger sample is comparable or that a selected
variable set is valid.

Hand-solvable tests verify a three-DMU frontier where the dominated unit has efficiency
0.5 and a single frontier peer. Additional tests cover positive unit rescaling and every
edge case listed above.

## Current fixture result and limitations

All 521 synthetic LPs solved successfully. The run identified 57 strongly efficient DMUs
(10.94%). This number describes only the selected synthetic cohort and variables. It must
not be reported as CE/IT efficiency, used as a multiplier on predicted outcomes, inserted
into the societal objective, or treated as evidence that inputs can be reduced in practice.

`efficiency.csv` is the complete score/target/slack table. `peers.csv` contains the peer
weights, and `peer_gap_explanations.md` explains modeled gaps for every synthetic DMU.
`summary.json` records data/config hashes, scaling factors, solver counts, discrimination
diagnostics, assumptions, and evidence status.

Institution-level peer rows must remain separate from departmental observations. Before
an empirical run, filter a cohort with aligned periods, currency base years, institutional
scope, and KPI definitions, then justify the selected inputs/outputs with stakeholders.

## Network DEA decision

Network DEA remains deferred. The repository has no observed intermediate stages such as
research production -> commercialization -> student/societal outcomes, and no defensible
linking variables between those stages. Adding a network structure now would encode
unverifiable synthetic relationships rather than improve the benchmark.
